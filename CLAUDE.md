# RTL Playground

Educational RTL/gate-level schematic editor and cycle simulator for a masters digital design course. See `DESIGN.md` for the architecture and roadmap, `RESEARCH.md` for the landscape survey.

## Layout
- `frontend/` TypeScript + Vite, no UI framework. `src/model` (design model, block library, netlist, geometry, serialize), `src/sim` (simulator, test runner), `src/hdl` (`emit.ts`/`testbench.ts`: blocks to SystemVerilog and to a Verilator testbench, DESIGN.md section 8), `src/ui` (store, canvas, panels, waveform), `src/host` (client for the Python host).
- `src/rtl_playground/` stdlib-only Python host: serves `static/` (the Vite build output, gitignored) and a small file/HDL API on loopback.
- Project workspace (DESIGN.md section 13): `project.py` (rtlp-project.json, SDC/ORFS config generation), `toolchain.py` (native vs docker/podman/udocker), `jobs.py` (one background job at a time, polled logs), `flows.py` (lint/test/synth/flow/power recipes), `reports.py` (ORFS metrics JSON, power from simulation activity), `tool_scripts/` (scripts copied into the toolchain: `rtlp_cocotb.py`, `rtlp_power.tcl`). Front end in `frontend/src/project/`. Tools image in `docker/`.
- `examples/*.rtlp` shipped designs, generated by `frontend/scripts/gen-examples.ts` (edit the script, not the JSON).
- `legacy/rtl_playground.html` the original single-file prototype; `deserialize()` migrates its JSON.

## Commands
- Front end: `cd frontend && npm install && npm run build` (type-checks, then builds into `src/rtl_playground/static/`). `npm test` runs Vitest. `npx vite-node scripts/gen-examples.ts` regenerates and validates the examples.
- SystemVerilog fidelity (needs Verilator 5 and Yosys, e.g. under `~/eda/env/bin`; set `RTLP_EDA_ENV` if elsewhere): `npx vite-node scripts/verify-sv.ts [example.rtlp ...]` lints, builds and runs every example's exported testbench under Verilator and checks it synthesizes under Yosys.
- Host: `uv run rtl-playground --no-browser --port 8765` from the repo root; `uv run --dev pytest` for the host tests.
- Dev loop: run the host on 8765, then `npm run dev` in `frontend/` (Vite proxies `/api`).
- Browser smoke test (needs `npx playwright install chromium` once): `node frontend/scripts/smoke.mjs <screenshot dir> "http://127.0.0.1:8765/#token=<token from host output>"`.
- Project view end to end (needs a toolchain): `node frontend/scripts/project-e2e.mjs <screenshot dir> "<url>"` on a host serving an empty folder; `SKIP_FLOW=1` stops after lint and test.
- Toolchain env: `RTLP_TOOLCHAIN=native|docker|none`, `RTLP_ENGINE=docker|podman|udocker`, `RTLP_IMAGE`, `RTLP_TOOLS_PATH`, `RTLP_TOOLS_PYTHON`, `RTLP_ORFS_FLOW`, `RTLP_UDOCKER`.

## Conventions
- The design model is the single source of truth; simulation, rendering, tests and (later) HDL derive from it. Never mutate the design outside `store.mutate` / `store.begin`+`touch`+`end`, except input stimulus via `store.stimulus`.
- Block semantics live only in `src/model/library.ts`; keep them aligned with Yosys cell semantics for the future HDL import.
- Values are `bigint`; JSON stores numbers when safe, strings otherwise.
- Reset is synchronous active-high; HDL output is SystemVerilog only.
- SDC times are generated in the platform's Liberty unit (ASAP7 is ps, the rest ns). Setup and hold uncertainty are separate on purpose: a setup-sized hold margin makes OpenROAD bury ASAP7 designs in hold buffers (RSZ-0060).
- `tests/fixtures/orfs_sad_pe` holds real ORFS metrics; refresh it when bumping the ORFS image.
